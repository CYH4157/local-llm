# 自架 vLLM × opencode 使用教學（Windows 版）

實驗室用一台 **Windows 筆電** 跑語言模型（vLLM），筆電本身和實驗室同學的電腦都用 **opencode** 連上它，
拿來寫程式、查生活資訊、寫作業查資料。模型、程式碼和對話都留在實驗室，不經過任何雲端 API。

> 投影片：repo 的 `docs/實驗室本地LLM使用教學.pptx`；全部步驟總整理：repo 根目錄的 `完整步驟.md`。所有數據都是在實驗室筆電
> （RTX 5070 Ti Laptop 12GB、Windows 11 Home 26200）實測的結果。

## 1. 系統架構

```
 Windows 筆電（主機，例：192.168.1.23）                        同學的電腦（Windows / Ubuntu）
 ├─ WSL2 Ubuntu（mirrored 網路：和筆電共用同一個 IP）              └─ opencode ─┐
 │   └─ vLLM :8000（systemd 服務 vllm，需 API 金鑰） ◀──────────────────────────┘ http://筆電IP:8000/v1
 ├─ opencode（Windows 版，終端機或桌面版）→ http://127.0.0.1:8000/v1
 ├─ 排程 vLLM-WSL-KeepAlive：登入後讓 WSL 常駐，每 5 分鐘自動檢查
 └─ 防火牆：TCP 8000 只允許同網段
```

| 元件 | 作用 |
|------|------|
| **vLLM** | 推論伺服器。把模型載入 GPU，提供 OpenAI 相容 API，支援 tool calling（opencode 讀寫檔案靠它） |
| **WSL2** | Windows 內建的 Linux。vLLM 只能在 Linux 執行，所以放在這裡 |
| **opencode** | AI 寫程式助手（[github.com/anomalyco/opencode](https://github.com/anomalyco/opencode)）。有終端機版與桌面版 |

**只有筆電跑模型**。同學的電腦不需要 GPU，也不用裝 vLLM，只要連得到「筆電 IP:8000」。

## 2. 開始前的準備

**筆電（主機）**

| 項目 | 說明 |
|------|------|
| Windows 11 22H2 以上 | WSL mirrored 網路需要（同學才連得到） |
| NVIDIA 顯示卡 8GB 以上 | 到 NVIDIA 官網裝最新版驅動。**不要**在 WSL 裡另外裝驅動 |
| 硬碟約 30GB | WSL、vLLM（約 8GB）、模型（4~6GB） |
| 系統管理員權限 | 安裝時需要，日常使用不用 |
| 固定 IP | 請網管或在路由器幫筆電設 DHCP 保留，否則 IP 一變同學就要重設 |

**同學的電腦**：Windows 10/11 或 Ubuntu，和筆電在同一個網路即可。

## 3. 筆電（主機）安裝

### 3.1 一鍵安裝

1. 把整個專案放到筆電：`git clone https://github.com/CYH4157/local-llm.git`（或下載 ZIP 解壓縮），vLLM 相關腳本在 `opencode` 資料夾裡。
2. **雙擊 `server\wsl2\setup-host.cmd`**，同意系統管理員權限。
3. 第一次執行如果還沒有 WSL：腳本會自動安裝 Ubuntu → **重新開機** → 從開始選單開「Ubuntu」設定使用者名稱與密碼 → **再雙擊一次** `setup-host.cmd`。
4. 出現 `[sudo] password for 你的帳號:` 時輸入 **Ubuntu 密碼**（打字不會顯示）。
5. 第一次約 20~40 分鐘（下載約 15GB）。結束時會印出要給同學的 **網址、API 金鑰、模型名稱**。

> Ubuntu 密碼忘了或沒設過：在 PowerShell 執行 `wsl -d Ubuntu -u root passwd 你的Ubuntu帳號` 重設。

### 3.2 腳本自動做的事

| 步驟 | 內容 |
|------|------|
| 1 | 檢查 NVIDIA 驅動、Windows 版本 |
| 2 | 偵測 WSL：已有 Ubuntu（含 `Ubuntu-24.04` 這類名稱）就沿用；WSL1 自動轉 WSL2；沒有才安裝 |
| 3 | WSL 改 **mirrored 網路**（`%USERPROFILE%\.wslconfig`），和筆電共用 IP |
| 4 | 註冊排程 **vLLM-WSL-KeepAlive**：背景執行、不跳視窗，每 5 分鐘檢查 WSL 有沒有在跑 |
| 5 | 在 WSL 裡執行 `setup-vllm.sh`：開啟 systemd、裝 uv 與 vLLM、依顯存選模型、產生金鑰、註冊開機自動啟動的 `vllm` 服務 |
| 6 | 防火牆開放 TCP 8000（Windows 防火牆 + WSL 的 Hyper-V 防火牆），預設只允許同網段 |
| 7 | 電源：接上電源時不睡眠、闔上螢幕不動作（用電池時不變） |
| 8 | 安裝 opencode 桌面版（並自動避開 WSL 保留的 port），連到本機 vLLM，並安裝全域規則檔 |

**RTX 50 系列（Blackwell）的相容處理**：vLLM 在新顯卡上預設會用 DeepGEMM / FlashInfer，執行時要現場編譯 CUDA，
需要完整的 CUDA Toolkit。腳本會自動改用不需要編譯的元件（`VLLM_USE_DEEP_GEMM=0`、`SERVE_ATTN_BACKEND=TRITON_ATTN`、
`VLLM_USE_FLASHINFER_SAMPLER=0`），不必另裝 CUDA Toolkit。

### 3.3 安裝參數

在 PowerShell 執行 `server\wsl2\setup-host.cmd -參數`：

| 參數 | 說明 |
|------|------|
| `-Preset small/laptop/quality/medium/large` | 指定模型組合（預設依顯存自動選，12GB = `laptop`） |
| `-EnableSsh` | 開啟 Windows OpenSSH 伺服器，讓同學 ssh 進來用筆電上的 opencode |
| `-AllowFrom 來源清單` | 允許連線的來源，逗號分隔。預設 `LocalSubnet`（同網段）；可加網段，例 `LocalSubnet,10.8.0.0/16`（見 [10.2](#102-在家透過學校-vpn-連線)）；`Any` = 不限制 |
| `-AllowSleep` | 不更改電源設定 |
| `-SkipOpencode` | 筆電只當模型主機，不裝 opencode |
| `-SkipVllm` | vLLM 已裝好，只重做 Windows 端設定（防火牆、電源、排程、opencode） |

### 3.4 重要提醒

- **重開機後要先登入 Windows**，排程才會啟動 WSL；模型約 1 分鐘載入完成。
- 筆電請**接上電源**。
- 之後想看連線資訊：雙擊 `server\wsl2\vllmctl.cmd`，輸入 `info`。

## 4. 同學的電腦安裝

### 4.1 Windows（建議）

> **管理者可以先把網址和金鑰填好**：複製 `opencode\servers.example.json` 成 `opencode\servers.json`、填入金鑰，
> 再把整個 `opencode` 資料夾私下給同學；同學雙擊 `install-client.cmd` 就會自動加入裡面的每一台，不用輸入。
> 詳細欄位說明在 servers.example.json 裡。servers.json 有金鑰，已列在 `.gitignore`，不會上傳。

1. 把 `opencode` 資料夾複製過去（只需要 `client` 資料夾，**整個資料夾**都要，不能只複製 .cmd）。
2. **雙擊 `opencode\client\install-client.cmd`**，貼上筆電給的 **網址**（例 `http://192.168.1.23:8000/v1`）與 **API 金鑰**。
3. 腳本會：測試連線 → **安裝 opencode 桌面版**（約 250MB，只裝給自己、不需系統管理員）→ 寫入 `%USERPROFILE%\.config\opencode\opencode.json` → 安裝全域規則檔。
4. **開始選單搜尋「OpenCode」**開啟 → 開啟你的專案資料夾 → 模型選單選 `laptop` 底下的模型。

> 習慣終端機的同學可以加 `-Terminal`，另外安裝終端機版（見 4.4）。桌面版和終端機版共用同一份設定。

### 4.2 Ubuntu（例如伺服器主機）

```bash
bash opencode/client/install-client.sh --url http://192.168.1.23:8000/v1 --key sk-vllm-xxxx --name laptop
```

### 4.3 加入國網中心 GenAI API（選用）

有申請國網中心 GenAI 的 API 金鑰的話，可以把國網的大模型也加進 opencode，跟實驗室的模型並存：

**管理者有發 `servers.json` 的話**：裡面已經有 `nchc` 這一筆（範本 `servers.example.json` 就有），
雙擊 `install-client.cmd` 時會跟實驗室的模型一起加入，執行到國網那一台時貼上**自己的**國網 API 金鑰（`sk-` 開頭）即可。

**沒有 `servers.json`、只想加國網**：在 PowerShell 執行（金鑰會在執行時詢問）：

```
opencode\client\install-client.cmd -Url https://inner-medusa.genai.nchc.org.tw/v1 -Name nchc -Label "NCHC GenAI" -Context 32768 -Models "gpt-oss-120b,gpt-oss-20b,GLM-5.2,GLM-5.3-max,gemma-4-31B-it-with-tool,gemma-4-26B-A4B-it,Llama-3.3-70B-Instruct,NVIDIA-Nemotron-3-Super-120B-A12B,Mistral-Large-3-675B-Instruct-2512,Thanos3.5-397B-A17B"
```

- 只加入實測能呼叫工具（opencode 讀寫檔案需要）的模型；原本的預設模型不會被改掉。
- 在 opencode 的模型選單（終端機版 `/models`）選 `NCHC GenAI` 底下的模型。
- 模型清單以 `servers.example.json` 為準；國網換模型時改那裡即可。

> 國網的模型跑在國網中心，**對話內容會送到國網**，不像實驗室的模型留在本地；機密資料請用實驗室的模型。
> 國網沒有回報各模型的上下文長度，一律設成 32k。

### 4.4 終端機版（選用）

`install-client` 預設只裝桌面版。想在終端機裡用 opencode 的話，加 `-Terminal`（用 Scoop 安裝，不需系統管理員）：

```
opencode\client\install-client.cmd -Terminal
```

裝好後開一個**新的**終端機，`cd` 到專案資料夾，輸入 `opencode`。

> **主機筆電上的桌面版「Managed service port … already in use」**：WSL mirrored 模式會把一段埠號保留給 Linux，
> 桌面版隨機挑到就會失敗。`install-client` 偵測到 mirrored 網路時會**自動**把桌面版固定到保留範圍外的埠（14096）。
> 手動處理：`& "$env:LOCALAPPDATA\Programs\@opencodedesktop\resources\opencode-cli.exe" service set port 14096`，再重開桌面版。

### 4.5 加入其他伺服器的模型（不用重裝）

opencode 程式只要裝一次。之後每多一台伺服器（例如另一台 GPU 主機、國網），再跑一次 `install-client`、
**換一個 `-Name`、加上 `-SkipInstall`**，就會新增一組模型，原本的不會被蓋掉：

```
opencode\client\install-client.cmd -Url http://另一台IP:8000/v1 -Key 那台的金鑰 -Name server2 -SkipInstall
```

- 任何 **OpenAI 相容**的 API 都可以（網址結尾是 `/v1`，有 `/v1/models` 與 `/v1/chat/completions`）。
- 重開 OpenCode，在模型選單（終端機版是 `/models`）就能切換 `laptop/…`、`server2/…`。
- 要讓預設模型改成新的那台，加 `-Default`。
- 管理者也可以把多台都寫進 `servers.json`，同學雙擊一次就全部加入（見 4.1 上方說明）。
- 移除某一台：`opencode\client\uninstall-client.cmd -Name server2 -KeepProgram`。

## 5. 使用 opencode

### 5.1 啟動

```powershell
cd C:\Users\你\Documents\你的專案
opencode
```

畫面下方顯示 `laptop/qwen3-4b` 代表正在用筆電的模型。**第一次進專案先輸入 `/init`**，
它會產生 `AGENTS.md` 說明專案結構，小模型有了它表現好很多。

### 5.2 常用指令

| 輸入 | 作用 |
|------|------|
| 直接打字 + Enter | 用中文描述需求 |
| `/init` | 分析專案、產生 AGENTS.md |
| `@檔名` | 指定檔案，例 `@src/train.py` |
| `Tab` | 切換 **Build**（會改檔）/ **Plan**（只分析不改） |
| `/models` | 切換模型 |
| `/undo` · `/redo` | 復原 / 重做上一次修改 |
| `/new` · `/compact` | 開新對話 / 壓縮過長的對話 |
| `/exit` 或 `Ctrl+C` | 離開 |

### 5.3 讓小模型好用的提問方式

- **一次一件事**：「在 `utils.py` 加一個讀 CSV 的函式」比「重構整個專案」可靠。
- **寫出相對路徑、用 `@` 指定檔案**：小模型偶爾會把檔案寫到 `C:\`（opencode 會擋下）。
- **先 Plan 再 Build**：Tab 切到 Plan 讓它列步驟，確認後再執行。
- **用中文提問**：回答會是繁體中文；用英文問約一半會回英文。
- **查生活資訊時講清楚要最新的**，或直接給官網網址。opencode 主要是寫程式的工具，查時事不是強項。

### 5.4 全域規則檔

安裝時會把 `client/opencode-rules.md` 裝成 `~/.config/opencode/AGENTS.md`，每次對話都會帶給模型：

- **寫程式**：只用專案內的相對路徑、只改要求的範圍、刪檔或裝套件前先確認
- **查生活資訊**：先確認今天日期、只列進行中或即將發生的、附來源網址與日期
- **作業 / 研究**：引用附出處、不捏造參考文獻、提醒自行改寫並遵守學術誠信
- 回答用繁體中文

已經有自己的 `AGENTS.md` 時不會覆蓋。實驗室要改規則：改 `client/opencode-rules.md` 後讓大家重跑 `install-client`。

### 5.5 文件與行政指令（做投影片、PDF 轉 Word、簽呈…）

安裝時會一起裝文件工具 **labdoc** 和下面這些 `/指令`。在 opencode 輸入 `/` 就會列出來，後面接你的需求或檔名：

| 指令 | 用途 | 例子 |
|------|------|------|
| `/slides` | 做投影片（.pptx） | `/slides 期中進度報告，參考 @筆記.md` |
| `/word` | 寫 Word 文件 | `/word 迎新活動企劃書，日期 11/15` |
| `/excel` | 做 Excel 表格 | `/excel 把 @報名.txt 整理成名單` |
| `/pdf2word` | PDF 轉可編輯的 Word | `/pdf2word 計畫書.pdf` |
| `/pdf` | 合併、取出頁、刪頁、旋轉、照片轉 PDF、壓縮、Office 轉 PDF | `/pdf 把 a.pdf 和 b.pdf 合併` |
| `/summary` | 摘要公告或文件：重點、期限、要做的事 | `/summary 獎學金公告.pdf` |
| `/official` | 簽呈、公文、申請書、請假單（台灣公文格式，標楷體） | `/official 簽呈：申請購買 4 顆硬碟` |
| `/email` | 寫信給老師、行政、廠商（中英文） | `/email 跟老師請假下週三的 meeting` |
| `/minutes` | 筆記或逐字稿整理成會議紀錄（Word） | `/minutes @1024會議筆記.txt` |
| `/expense` | 收據清單整理成核銷支出明細（Excel，自動合計） | `/expense @十月收據.txt` |
| `/todo` | 從訊息、公告整理待辦與期限 | `/todo`（再貼上群組訊息） |
| `/proofread` | 校稿（台灣繁體）：簡體字、大陸用語、錯字、標點、語句 | `/proofread 論文第二章.docx` |
| `/translate` | 中英翻譯，長文件輸出 Word | `/translate abstract.pdf 翻成中文` |

**運作方式**：模型只負責寫內容（Markdown 檔），排版與轉檔交給 labdoc，所以小模型也能穩定產生格式正確的檔案。
產生的檔案放在專案資料夾裡；同名檔案已存在時會自動加 `(1)`，不會覆蓋原檔。不滿意可以直接說「第三張改成…」，
它會改 Markdown 再重新產生。

**台灣用語**：回答一律用繁體中文與台灣用語。另外 labdoc 會用 OpenCC 字典加實驗室補充詞表比對，比小模型自己判斷可靠：
- `labdoc word` / `slides` / `excel` 產生檔案時，會**自動**把簡體字、大陸用語（軟件→軟體、服務器→伺服器、質量→品質…）
  和中文句子裡的半形標點改掉，並列出改了哪些詞；不想改加 `--keep-terms`。
- `labdoc tw 檔名` 只檢查不修改；`--fix` 另存「原檔名_台灣用語」修正版（Word、PPT 保留原本格式；PDF、Excel 只檢查）。
- 「支持、項目、程序、窗口、數據」這類台灣也常用、要看意思的詞只會提醒，不會自動改；「台」「臺」都不改。
- 補充詞表在 `labdoc.py` 的 `TW_EXTRA`（要改的詞）和 `TW_CONTEXT`（只提醒的詞），發現漏掉的詞可以加進去後重跑 install-client。

**限制**：
- 掃描版 PDF 和照片讀不到文字（不做 OCR）；請先用 Word 開啟 PDF 或手機文字辨識轉成文字。
- 轉 PDF（`/pdf` 的 Office 轉 PDF）需要電腦裝有 Microsoft Office；Ubuntu 要裝 LibreOffice。
- 內容由 4B 小模型撰寫，數字、人名、日期一定要自己核對；缺的資料會留「［請填：…］」。
- 舊格式 `.doc` / `.ppt` / `.xls` 請先另存成新格式。

**也可以直接用 labdoc**（PowerShell 或終端機）：

```powershell
labdoc read 公告.pdf               # 印出文字
labdoc pdf2word 計畫書.pdf
labdoc slides 報告.md              # Markdown → PowerPoint（# 封面、## 每張、> 講者備註）
labdoc word 簽呈.md --template 學校範本.docx
labdoc excel 支出.md --total
labdoc pdf merge a.pdf b.pdf -o 合併.pdf
labdoc tw 報告.docx --fix             # 簡體字、大陸用語 → 台灣用語（另存新檔）
labdoc -h                          # 全部用法
```

安裝位置：`%USERPROFILE%\.config\opencode\labdoc\`（獨立的 Python 環境，約 400MB，不影響你自己的 Python）；
指令檔在 `%USERPROFILE%\.config\opencode\command\`。自己改過的指令檔把第二行的 `lab-opencode-command` 刪掉，重裝時就不會被覆蓋。
不想裝文件工具：`install-client.cmd -SkipTools`（Ubuntu：`--skip-tools`）。
只要文件工具、不連 vLLM（例如用國網或 opencode 內建的模型）：雙擊 **`install-tools.cmd`**（Ubuntu：`bash install-client.sh --tools-only`），
會安裝 opencode、全域規則、labdoc 與 /指令，不會改動 `opencode.json` 的模型設定；之後要連 vLLM 再照一般方式執行 install-client。

## 6. 日常管理：vllmctl

在筆電 **雙擊 `server\wsl2\vllmctl.cmd`** 再輸入指令，或在終端機執行 `server\wsl2\vllmctl.cmd 指令`。
需要密碼時輸入 Ubuntu 密碼。

| 指令 | 作用 |
|------|------|
| `info` | 顯示給同學的網址、金鑰、安裝方式 |
| `show` | 目前所有設定（金鑰遮蔽）、GPU 用量、KV cache 容量 |
| `status` · `logs` | 服務狀態 / 即時紀錄（Ctrl+C 離開） |
| `start` · `stop` · `restart` | 啟動 / 停止（釋放 GPU 給其他程式）/ 重啟 |
| `presets` | 列出內建模型組合 |
| `preset 名稱` | 換成內建組合 |
| `model HF模型ID [名稱] [上下文] [tool parser]` | 換成任意模型 |
| `models` | 列出用過的模型（`*` = 使用中），每個模型的設定都會保留 |
| `switch [名稱或編號]` | 切換到用過的模型或內建組合；不加參數會列出選單 |
| `forget 名稱` | 從清單移除一個模型（權重檔不刪） |
| `set 參數 值` | 修改一個參數並重啟 |
| `new-key [金鑰]` | 產生新的 API 金鑰（或指定金鑰） |
| `edit` | 用 nano 編輯 `vllm.env`，存檔後重啟 |
| `bench` | 跑標準測試，結果存在 WSL 的 `~/bench-results/` |

## 7. 換模型

### 換模型流程（總覽）

| 步驟 | 做什麼 | 指令 / 說明 |
|------|--------|------------|
| 0 | 確認管理腳本是最新版（第一次用 `models` / `switch` 前） | `server\wsl2\setup-host.cmd -SkipVllm`（見 7.8） |
| 1 | 選模型：支援 tool calling、Instruct 版、顯存放得下 | 7.1、7.7 |
| 2 | 授權模型（Llama、Gemma…）先設 Hugging Face token | `vllmctl.cmd set HF_TOKEN hf_xxx`（9.2） |
| 3 | 換模型（**先下載完才切換**，下載期間大家照常用） | 內建組合 `preset quality`，或任意模型 `model <HF ID> <名稱> <上下文> <parser>` |
| 4 | 跑測試 | `vllmctl.cmd bench` |
| 5 | 不滿意就換回去（設定保留、不用重新下載） | `vllmctl.cmd switch qwen3-4b` |
| 6 | 通知同學重跑 `install-client`（預設模型會自動更新） | 7.5 |
| 7 | Discord bot | 不用動，`!model` 確認 |

### 7.1 選模型的原則

1. **一定要支援 tool calling**：opencode 讀寫檔案、執行指令都靠它。Qwen2.5 / Qwen3 系列都支援。
2. **上下文比模型大小重要**：opencode 每次請求光系統提示加工具定義就約 1 萬 token，再加程式碼或網頁。至少 16k，建議 32k。
3. **顯存要同時放「權重」和「KV cache（每個人的對話記憶）」**：

```
需要的顯存 ≈ 模型權重 + KV cache + 約 1~1.5GB 執行開銷
KV cache 每 token ≈ 2 × 層數 × KV heads × head 維度 × 每個數值的 bytes（FP8 = 1）
例：Qwen3-4B / 8B 都是 36 層、8 個 KV heads、head 維度 128 → FP8 每 token 約 74KB
```

可用顯存 = 總顯存 × `SERVE_GPU_UTIL`。實驗室筆電：12GB × 0.85 ≈ 10.4GB。

| 模型 | 權重 | 32k 時能同時跑幾個長對話（12GB 筆電實測） |
|------|------|------|
| Qwen3-4B-Instruct-2507-FP8 | 4.26GB | **2.48 個**（KV 81,312 tokens） |
| Qwen3-8B-AWQ | 5.71GB | 1.83 個（KV 59,856 tokens） |
| Qwen3-14B-AWQ | ~9.5GB | 放不下（沒空間給 KV） |

### 7.2 內建組合

| 組合 | 顯存 | 模型 | 上下文 | 說明 |
|------|------|------|--------|------|
| `small` | 8~10GB | Qwen3-4B-Instruct-2507-FP8 | 16k | 8GB 筆電 |
| `laptop` | 11~15GB | Qwen3-4B-Instruct-2507-FP8 | 32k | ★ 實驗室筆電實測建議 |
| `quality` | 11~15GB | Qwen3-8B-AWQ（不思考模式） | 32k | 實測較慢、同時人數較少 |
| `medium` | 16~45GB | Qwen3-14B-AWQ（不思考模式） | 32k | H100-20C vGPU、RTX 4090 / 5090；未實測 |
| `large` | 46~99GB | Qwen3-Coder-30B-A3B-Instruct-FP8 | 64k | H100 80GB、A100 80GB、L40S；未實測 |
| `xlarge` | 100GB+ | Qwen3-Coder-30B-A3B-Instruct-FP8 | 128k | H200 141GB；同時 32 人；未實測 |

**安裝時會依顯卡自動調整**（不用手動設定）：

| 顯卡 | 自動選的組合 | 注意力後端 | 其他 |
|------|------|------|------|
| RTX 4070 Laptop 8GB | `small` | Triton（沒裝 CUDA Toolkit 時） | |
| RTX 4070 桌機 12GB | `laptop` | Triton（沒裝 CUDA Toolkit 時） | |
| RTX 5070 Ti Laptop 12GB | `laptop` | Triton（RTX 50 沒裝 CUDA Toolkit 時；有裝就用 vLLM 預設） | |
| RTX 3090 / A100（Ampere） | 依顯存 | FlashAttention | KV cache 不用 FP8（沒有 FP8 硬體） |
| H100-20C vGPU 20GB | `medium` | FlashAttention | 驅動只到 CUDA 12.x → 自動裝 vLLM 的 CUDA 12.9 版 |
| H100 80GB | `large` | FlashAttention | |
| H200 141GB | `xlarge` | FlashAttention | |

為什麼 RTX 40 / 50 用 Triton：沒有 CUDA Toolkit（nvcc）時，RTX 50 預設的 FlashInfer 會在暖機時現場編譯失敗；
RTX 30 / 40 的 FlashAttention 不支援 FP8 KV cache，vLLM 也會改找 FlashInfer。H100 / H200 的 FlashAttention 支援，所以交給 vLLM。

注意力後端存在 `vllm.env` 的 `SERVE_ATTN_BACKEND=auto`，**每次啟動時才依顯卡決定**，所以整個 `~/vllm-server` 搬到別台也不會用錯。
要強制指定：`vllmctl set SERVE_ATTN_BACKEND FLASH_ATTN`（或 `TRITON_ATTN`、`FLASHINFER`），改回自動：`vllmctl set SERVE_ATTN_BACKEND auto`。
舊版腳本把 RTX 50 用的 Triton 也套到 H100 / H200 上（H200 實測會卡住、每秒 0 token）；重跑 `setup-vllm.sh` 會自動改成 `auto`。

```
vllmctl.cmd presets          ← 列出組合
vllmctl.cmd preset quality   ← 換成 8B
vllmctl.cmd preset laptop    ← 換回建議設定
```

### 7.3 換成任意模型

```
vllmctl.cmd model Qwen/Qwen3-8B-AWQ qwen3-8b 32768 hermes
```

| 欄位 | 說明 |
|------|------|
| HF 模型 ID | Hugging Face 上的名稱，例 `Qwen/Qwen3-8B-AWQ` |
| 名稱 | opencode 裡看到的名字（同學設定也會用這個） |
| 上下文 | 單一對話上限（token），顯存不夠就調小 |
| tool parser | 依模型系列選，見下表；選錯的話 opencode 回應裡會直接出現 `<tool_call>` 之類的文字 |

| 模型系列 | tool parser |
|------|------|
| Qwen2.5、Qwen3（含 2507） | `hermes` |
| Qwen3-Coder | `qwen3_coder` |
| Llama 3.1 / 3.2 / 3.3 | `llama3_json` |
| Llama 4 | `llama4_pythonic` |
| Mistral | `mistral` |
| Gemma 4 | `gemma4` |
| GLM-4.5 | `glm45` |
| gpt-oss | `openai` |

> 以上名稱是實驗室筆電的 vLLM 0.31 支援的清單；其他模型查 vLLM 文件「Tool Calling」一節。

`model` 會**先下載完再切換**（服務中斷約 1 分鐘），並把 `SERVE_EXTRA_ARGS` 重設為基本值。
**思考型模型**（例 Qwen3-8B / 14B 原版）建議關掉思考模式，回答會快很多。這個參數含 JSON 雙引號，
從 Windows 用 `set` 傳會被吃掉，請用 `vllmctl.cmd edit` 把那一行改成（`\"` 照打）：

```
SERVE_EXTRA_ARGS="--kv-cache-dtype fp8 --enforce-eager --max-num-seqs 4 --reasoning-parser qwen3 --default-chat-template-kwargs {\"enable_thinking\":false}"
```

或直接用內建的 `quality` 組合（已經設好）。

需要授權的模型（Llama、Gemma 等）先設定 Hugging Face token，見 [9.2](#92-hugging-face-token)。

### 7.4 在用過的模型之間切換

用 `preset` / `model` 換過的模型會記在清單裡（`~/vllm-server/models/`），之後用 `switch` 就能換回去，
上下文、`SERVE_EXTRA_ARGS` 等設定（包括用 `set` / `edit` 調過的）都會保留，權重也不必重新下載：

```
vllmctl.cmd models              ← 列出用過的模型
vllmctl.cmd switch              ← 列出選單，輸入編號或名稱
vllmctl.cmd switch qwen3-14b    ← 直接切換
vllmctl.cmd switch quality      ← 也可以切到內建組合
```

Ubuntu 主機（沒有 Windows）直接執行 `./vllmctl.sh models`、`./vllmctl.sh switch`。
vLLM 同一時間只載入一個模型，所以切換時服務會中斷約 1 分鐘；名稱改變後一樣要做 7.5 的事。

### 7.5 換完一定要做的事

1. **跑測試**：`vllmctl.cmd bench`（約 1 分鐘），確認長文件、工具呼叫、速度都正常。
2. **通知同學重跑 `install-client`**：模型名稱或上下文改變後，opencode 的設定要更新。筆電自己也要重跑
   （`opencode\client\install-client.cmd -Url http://127.0.0.1:8000/v1 -SkipInstall`）。原本的預設模型若已不存在，會自動改成新模型。
3. **Discord bot（repo 根目錄）不用改**：它每次都會自動抓 vLLM 目前的模型。

### 7.6 實測比較（實驗室筆電）

| 測試 | 4B · 16k | **4B · 32k（建議）** | 8B-AWQ · 32k |
|------|----------|------------------|--------------|
| 生成速度（單人） | 28.7 tok/s | 27.5 tok/s | 26.9 tok/s |
| 長文件 2.1 萬 token | ❌ 超過上限 | ✅ 9.6 秒 | ✅ 17.2 秒 |
| 工具呼叫 | ✅ | ✅ | ✅ |
| 五人同時（總吞吐 / 最慢等待） | 61 tok/s / 6.7s | **121 tok/s / 3.4s** | 98 tok/s / 4.1s |
| 寫程式（執行驗證 6 個案例） | — | ✅ 6/6 | ❌ 3/6（同票規則寫錯） |
| 中文解釋 | 正確 | 正確 | 較專業，但有一句錯誤 |

結論：**8B 沒有比較好**。4B（2507 新版）程度已接近舊版 8B，而且快、能同時服務更多人。

### 7.7 使用 Hugging Face 上的其他模型（例：Llama 3.2）

vLLM 是直接從 Hugging Face 下載模型，所以 Hugging Face 上的模型大多可以用，條件如下：

| 條件 | 說明 | 以 Llama 3.2 為例 |
|------|------|------|
| 要用 **Instruct** 版 | 沒有 Instruct 的是基礎模型，不會對話 | `meta-llama/Llama-3.2-3B-Instruct` |
| **授權模型**先申請 | 在模型頁面同意授權條款，再設定 token（9.2） | Meta 的 Llama 要；Qwen 不用 |
| **顯存**放得下 | 權重 + KV cache（7.1）。12GB 筆電大約到 8B（量化版） | 1B、3B 可以；11B Vision 放不下 |
| **vLLM 支援的格式** | 原始權重（safetensors）或 AWQ / FP8 量化版。**GGUF 不建議**（vLLM 支援有限） | 用官方原始權重 |
| 支援 **tool calling** | opencode 讀寫檔案需要；parser 見 7.3 | `llama3_json` |

```
vllmctl.cmd set HF_TOKEN hf_xxxxxxxx
vllmctl.cmd model meta-llama/Llama-3.2-3B-Instruct llama3.2-3b 32768 llama3_json
vllmctl.cmd bench
```

> **期望值**：3B 這類小模型比預設的 Qwen3-4B-2507 弱，繁體中文、寫程式、工具呼叫都比較不穩。
> 一定要跑 `bench` 比較；不滿意就 `vllmctl.cmd switch qwen3-4b` 換回來。

### 7.8 換模型的注意事項

- **服務會中斷約 1 分鐘**：vLLM 一次只載入一個模型，切換時所有人（opencode、Discord bot）都會暫停。挑大家沒在用的時間，或先在群組通知。
- **下載不影響使用**：`model` / `switch` 會先下載完才切換，下載期間照常服務。第一次下載大約 3~20GB，看模型大小。
- **硬碟空間**：每個下載過的模型都留在 WSL 的 `~/.cache/huggingface/hub/`，`forget` 只從清單移除、**不刪權重**。
  新版 Hugging Face 快取把權重放在共用的 `hub/blobs/`，**直接刪 `models--…` 資料夾不會釋放空間**，請用官方工具：
  ```
  wsl -d Ubuntu -- ~/vllm-server/.venv/bin/hf cache ls                          ← 列出模型與大小
  wsl -d Ubuntu -- ~/vllm-server/.venv/bin/hf cache rm model/Qwen/Qwen3-8B-AWQ  ← 刪除（不要刪目前正在用的）
  ```
  Ubuntu 主機直接執行 `~/vllm-server/.venv/bin/hf cache ls` / `hf cache rm …`。
- **啟動失敗多半是顯存不足**：`vllmctl.cmd set SERVE_MAX_LEN 16384` 調小上下文，或 `set SERVE_GPU_UTIL 0.80`；還是不行就換小一點的模型。
  `vllmctl.cmd switch` 隨時可以換回原本能用的模型。
- **思考型模型**（Qwen3 原版、GLM 等）建議關掉思考模式，見 7.3。
- **模型名稱改了**：同學要重跑 `install-client`；`servers.json` 裡有寫 `models` 的話，名稱也要一起改。
- **管理腳本要是最新版**：`models`、`switch` 是後來加的指令。WSL 裡的腳本只在執行 `setup-host` 時更新，
  所以 repo 更新後要執行一次 `server\wsl2\setup-host.cmd -SkipVllm`（不會重裝 vLLM）。
  ⚠️ 之前用 `-AllowFrom` 加過 VPN 網段的話，這次也要帶上同樣的 `-AllowFrom`，否則防火牆會回到只允許同網段。

## 8. 修改 vLLM 參數

所有參數都在 WSL 的 `~/vllm-server/vllm.env`。用 `vllmctl.cmd show` 看目前設定，用 `set` 修改
（含雙引號的值請改用 `vllmctl.cmd edit`）：

```
vllmctl.cmd set SERVE_MAX_LEN 24576
vllmctl.cmd set SERVE_GPU_UTIL 0.80
```

### 8.1 參數說明

| 參數 | 說明 | 目前值 |
|------|------|--------|
| `SERVE_MODEL` | Hugging Face 模型 ID | `Qwen/Qwen3-4B-Instruct-2507-FP8` |
| `SERVE_NAME` | opencode 看到的模型名稱 | `qwen3-4b` |
| `SERVE_MAX_LEN` | 單一對話的上下文上限（token） | `32768` |
| `SERVE_GPU_UTIL` | vLLM 可使用的顯存比例；安裝時偵測到桌面占用會自動調低 | `0.85` |
| `SERVE_TOOL_PARSER` | tool calling 解析器 | `hermes` |
| `SERVE_EXTRA_ARGS` | 其他 vLLM 參數（見下表） | `--kv-cache-dtype fp8 --enforce-eager --max-num-seqs 6` |
| `SERVE_ATTN_BACKEND` | 注意力運算後端；空白 = 自動，`TRITON_ATTN` = 不需 CUDA Toolkit | `TRITON_ATTN` |
| `SERVE_HOST` · `SERVE_PORT` | 綁定位址與埠號；只給筆電自己用就把 HOST 改 `127.0.0.1` | `0.0.0.0` · `8000` |
| `SERVE_API_KEY` | API 金鑰（見 [9.1](#91-api-金鑰)） | `sk-vllm-…` |
| `HF_TOKEN` | Hugging Face token（見 [9.2](#92-hugging-face-token)） | 空白 |
| `VLLM_USE_DEEP_GEMM` | RTX 50 系列需為 `0` | `0` |
| `VLLM_USE_FLASHINFER_SAMPLER` | RTX 50 系列需為 `0` | `0` |

**`SERVE_EXTRA_ARGS` 常用項目**

| 參數 | 說明 |
|------|------|
| `--kv-cache-dtype fp8` | 對話記憶用 FP8 存，容量約加倍 |
| `--enforce-eager` | 不建 CUDA graph：啟動快、省顯存 |
| `--max-num-seqs N` | 最多同時處理 N 個請求（超過的排隊）。5 人共用建議 6 |
| `--reasoning-parser qwen3` | 思考型模型把思考過程分開 |
| `--default-chat-template-kwargs {"enable_thinking":false}` | 關閉 Qwen3 的思考模式，回答更快 |
| `--tensor-parallel-size 2` | 兩張 GPU 時分攤模型 |

### 8.2 常見調整情境

| 情境 | 做法 |
|------|------|
| 啟動失敗、顯存不足 | `set SERVE_MAX_LEN 16384`，或 `set SERVE_GPU_UTIL 0.80` |
| 讀長文件、長對話常超過上限 | 加大 `SERVE_MAX_LEN`（12GB 筆電 4B 可到 32768） |
| 多人同時用很慢 | 調整 `--max-num-seqs`；先用 `show` 確認 KV cache 夠不夠 |
| 筆電要玩遊戲或跑其他 GPU 程式 | `vllmctl.cmd stop`，用完 `start` |
| 改完不確定有沒有變好 | `vllmctl.cmd bench` 前後比較 |

改了 `SERVE_NAME`、`SERVE_MAX_LEN`、`SERVE_MODEL`、`SERVE_PORT` 後，同學要重跑 `install-client`。

## 9. 金鑰與 Token

### 9.1 API 金鑰

vLLM 的每個請求都要帶 `Authorization: Bearer 金鑰`，沒有金鑰的人連得到也用不了。

| 操作 | 指令 |
|------|------|
| 查看目前金鑰 | `vllmctl.cmd info` |
| **產生新金鑰**（舊的立即失效） | `vllmctl.cmd new-key` |
| 改成指定的金鑰 | `vllmctl.cmd new-key sk-lab-自己取的名字` |

- 安裝時會自動產生一組 `sk-vllm-` 開頭的隨機金鑰。
- **換金鑰後，所有同學都要用新金鑰重跑 `install-client`**；筆電自己的 opencode 也要重跑。
  Discord bot 不用改，它會自動從 WSL 重讀金鑰。
- 有人離開實驗室、或金鑰外流時就換一組。只私下傳給實驗室成員。
- 同學的 Windows 電腦：金鑰寫在 `%USERPROFILE%\.config\opencode\opencode.json`，不要分享這個檔。

### 9.2 Hugging Face Token

下載**需要授權**的模型（Llama、Gemma 等）時才需要；Qwen 系列不需要。

1. 到 Hugging Face 模型頁面按同意授權條款。
2. 到 [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens) 建立 **Read** 權限的 token（`hf_` 開頭）。
3. 設定到筆電：`vllmctl.cmd set HF_TOKEN hf_xxxxxxxx`
4. 再用 `vllmctl.cmd model 模型ID …` 換模型。

### 9.3 什麼是 token、上下文、tok/s

- **token**：模型處理文字的單位，英文約 4 個字母一個，中文約 1~2 個字一個。
- **上下文（`SERVE_MAX_LEN`）**：一次對話能放進模型的 token 上限，包含系統提示、規則檔、程式碼、對話歷史與回答。超過就會報錯，opencode 裡用 `/compact` 或 `/new`。
- **tok/s**：每秒產生多少 token。實驗室筆電約 27 tok/s，比閱讀速度快很多。
- **KV cache**：模型對每個對話的「記憶」，佔顯存。`vllmctl.cmd show` 會顯示總容量（例 81,312 tokens）。

## 10. 網路與安全

- **網路前提**：同學要連得到筆電的 IP（同一個區網，或校內網路互通）。先用瀏覽器開 `http://筆電IP:8000/v1/models`，看到 `Unauthorized` 就代表連得到。
- **IP 會變**：筆電換網路 IP 就會變，請固定 IP。變了的話用 `vllmctl.cmd info` 查新的，同學重跑 `install-client`。
- **防火牆**：8000 埠預設只允許同網段（Windows 防火牆 + Hyper-V 防火牆）。其他網段（學校 VPN、伺服器）要連時，把該網段加進 `-AllowFrom`，見 [10.2](#102-在家透過學校-vpn-連線)。
- **不要開 port forwarding**：只在實驗室內部網路提供服務。
- **筆電用自己的區網 IP 連自己會失敗**：這是 WSL mirrored 模式的限制，不代表同學連不到，要用別台裝置測。

### 10.0 不在實驗室時，用哪種方式連？

| 使用者 | 方式 |
|------|------|
| 實驗室同學（在校內） | 區網 IP：`http://筆電IP:8000/v1` |
| **實驗室同學（在家）** | **先連學校 VPN**，其他跟在校內完全一樣（[10.2](#102-在家透過學校-vpn-連線)） |
| 校外合作者（沒有學校帳號） | Tailscale Funnel（[10.1](#101-校外連線tailscale-funnel)），用完就關 |

### 10.1 校外連線：Tailscale Funnel

需要讓**校外的人**（不在實驗室網路）使用時，用 Tailscale Funnel 把 vLLM 公開成一個 HTTPS 網址。
**對方的電腦不用裝 Tailscale**，跟校內同學一樣，用 `install-client` 貼上網址和金鑰就能用。

```
 網際網路上的 opencode ──HTTPS──▶ https://筆電名稱.你的tailnet.ts.net/v1 ──Tailscale──▶ 筆電 127.0.0.1:8000/v1（vLLM）
```

**第一次設定（只有管理者要做）**

1. 到 [tailscale.com](https://tailscale.com) 用自己的帳號（Google / Microsoft / GitHub 皆可）註冊。
2. 在筆電雙擊 **`server\wsl2\funnel.cmd`**，輸入 `on`。
   - 沒裝 Tailscale 時會自動安裝，接著從右下角系統匣的 Tailscale 圖示登入，再輸入一次 `on`。
   - 第一次會跳出瀏覽器，要你按「同意啟用 Funnel」，Tailscale 會自動開好 HTTPS 憑證和權限。
3. 完成後會印出公開網址，例如 `https://lab-laptop.tail1234.ts.net/v1`。第一次最多要等 10 分鐘 DNS 才生效。
4. 輸入 `test` 檢查：沒帶金鑰要被擋（401）、帶金鑰可以用（200）、`/metrics` 等其他路徑不能公開（404）。
   要確認外面真的連得到，可以用手機關掉 Wi-Fi，用瀏覽器開 `公開網址/models`，看到 401 就代表成功。

**給校外使用者**：公開網址（含 `/v1`）+ 金鑰 → 對方雙擊 `opencode\client\install-client.cmd` 貼上即可。

| `funnel.cmd` 指令 | 作用 |
|------|------|
| `on` | 開啟（重開機後會自動恢復，直到 `off`） |
| `off` | 關閉，外部立刻連不到（校內區網不受影響） |
| `status` | 目前設定 |
| `test` | 檢查金鑰保護與公開範圍 |

**安全須知**（Funnel 開啟後，**全世界都連得到這個網址**，唯一的保護是 API 金鑰）

- 只公開 `/v1`：vLLM 的金鑰只保護 `/v1/*`，`/metrics` 等路徑不需要金鑰。`funnel.cmd` 只公開 `/v1`，不要手動改成公開整個 8000 port。
- **給校外的人之前先換金鑰**（`vllmctl.cmd new-key`），合作結束再換一次。換金鑰後校內同學也要重跑 `install-client`。
- **不用時就 `off`**。
- 傳輸由 Tailscale 的 HTTPS 加密；Funnel 有頻寬限制（官方未公開數字），而且目前還是 beta 功能，不適合大量使用。
- 校外的人也是共用同一張顯卡，人多時大家都會變慢。

### 10.2 在家透過學校 VPN 連線

同學連上學校 VPN 後，電腦就等於在校內網路，**不用裝 Tailscale**。opencode 的設定跟在實驗室一樣，網址就是筆電的校內 IP。

**前提**：筆電要接在**實驗室的網路**上，不要接手機熱點（熱點的 IP 是 `172.20.10.x`，校內連不到），而且最好固定 IP。

**第一次設定（管理者 + 一位同學一起做，約 10 分鐘）**

1. **同學在家連上學校 VPN**，打開「命令提示字元」輸入 `ipconfig`，找 VPN 那張網卡的 IPv4 位址，例如 `10.8.23.45`。
2. **同學測試**：用瀏覽器開 `http://筆電IP:8000/v1/models`。
   - 看到 `Unauthorized` → 已經通了，直接跳到第 5 步。
   - 一直轉圈 → 被筆電的防火牆擋了（VPN 的 IP 跟實驗室不同網段），繼續第 3 步。
3. **問出 VPN 的網段**：最準確的是問計中「VPN 使用者會拿到哪個 IP 範圍」。
   不方便問的話，用第 1 步看到的 IP 推估，把最後兩段換成 `0.0/16`，例如 `10.8.23.45` → `10.8.0.0/16`。
4. **筆電加開 VPN 網段**（在 opencode 資料夾的 PowerShell 執行，會要求系統管理員權限）：
   ```
   server\wsl2\setup-host.cmd -SkipVllm -AllowFrom LocalSubnet,10.8.0.0/16
   ```
   `LocalSubnet` 要保留，不然實驗室裡的同學會被擋。學校有多個網段就用逗號接下去。之後同學重做第 2 步確認。
5. **同學安裝 opencode**：雙擊 `opencode\client\install-client.cmd`，貼上 `http://筆電IP:8000/v1` 和金鑰。之後在家只要先連 VPN 再開 opencode 即可。

**注意**

- **不要用 `-AllowFrom Any` 偷懶**：很多學校配給電腦的是公開 IP（`140.` 開頭），這時 `Any` 等於整個網際網路都連得到 8000 port，而且是沒加密的 HTTP。`setup-host` 偵測到這種情況會警告。
- **還是連不到**：學校 VPN 可能只開放連特定服務（例如圖書館），沒有開放連到實驗室網段，要請計中協助。
- **安全性**：VPN 連線到學校這一段有加密；校內這一段跟在實驗室一樣是 HTTP，靠 API 金鑰保護。

## 11. 疑難排解

**任何問題先看紀錄**：`vllmctl.cmd logs`。「Engine core initialization failed」只是總結，往上找第一個 `RuntimeError` 才是真正原因。

| 症狀 | 處理 |
|------|------|
| opencode 顯示 Cannot connect to API | vLLM 沒在跑：`vllmctl.cmd status`；WSL 被關掉的話排程最多 5 分鐘會自動恢復，或 `vllmctl.cmd start` |
| 重開機後大家都連不到 | 要先登入 Windows；工作排程器裡 `vLLM-WSL-KeepAlive` 要是「執行中」 |
| 啟動失敗、顯存不足（OOM、No available memory） | `set SERVE_MAX_LEN 16384` 或 `set SERVE_GPU_UTIL 0.80` |
| 紀錄有 `find_cuda_toolkit` 或 `Could not find nvcc` | RTX 50 相容設定沒套到：`set VLLM_USE_DEEP_GEMM 0`、`set SERVE_ATTN_BACKEND TRITON_ATTN`、`set VLLM_USE_FLASHINFER_SAMPLER 0` |
| WSL 裡看不到 GPU | 更新 Windows 端 NVIDIA 驅動，`wsl --shutdown` 後重跑 |
| 輸入 `opencode` 找不到指令 | 開一個**新的**終端機視窗 |
| 安裝時 Set-ExecutionPolicy 紅字、Scoop 沒裝 | 已在新版 `install-client` 修正；重跑即可 |
| 同學連不到、筆電本機可以 | IP 變了？不同網段（`-AllowFrom Any`）？Windows 11 22H2 以上？ |
| opencode 回應出現 `<tool_call>` 文字 | `SERVE_TOOL_PARSER` 要對應模型 |
| opencode 報超過 context 上限 | `/compact` 或 `/new`；常發生就加大 `SERVE_MAX_LEN` |
| 小模型把檔案寫到 `C:\` 被擋下 | 提問時寫出相對路徑；全域規則檔已提醒 |
| 桌面版「Managed service port … already in use」 | 見 [4.4](#44-桌面版有對話視窗的-ui) |
| Ubuntu 密碼忘了 | `wsl -d Ubuntu -u root passwd 你的Ubuntu帳號` |
| 只想重做防火牆 / 電源 / opencode | `server\wsl2\setup-host.cmd -SkipVllm` |

## 12. 檔案結構

```
local-llm/
├─ server/
│  ├─ wsl2/                       Windows 筆電（主機）用
│  │  ├─ setup-host.cmd / .ps1    一鍵安裝（雙擊 .cmd）
│  │  ├─ vllmctl.cmd              日常管理（雙擊）
│  │  ├─ funnel.cmd / .ps1        校外連線：Tailscale Funnel 開關（雙擊）
│  │  └─ uninstall-host.cmd / .ps1  解除安裝並還原設定（雙擊）
│  └─ vllm/                       在 Linux 執行的腳本（WSL：安裝時自動複製到 ~/vllm-opencode-setup；Ubuntu 主機直接執行）
│     ├─ setup-vllm.sh            安裝 vLLM、模型、金鑰、systemd 服務
│     ├─ vllmctl.sh               管理腳本（vllmctl.cmd 實際執行的就是它）
│     ├─ uninstall-vllm.sh        移除 vLLM（uninstall-host 呼叫）
│     ├─ lib.sh                   共用函式與模型組合
│     └─ bench.py                 標準測試
└─ opencode/
   ├─ client/                     同學的電腦用
   │  ├─ install-client.cmd / .ps1  Windows 一鍵安裝（雙擊 .cmd）
   │  ├─ install-client.sh        Ubuntu 安裝
   │  ├─ uninstall-client.cmd / .ps1 / .sh  解除安裝
   │  ├─ opencode-rules.md        全域規則檔
   │  ├─ labdoc/                  文件工具（讀檔、PDF 轉 Word、Markdown 轉 Office、PDF 合併拆頁）
   │  └─ commands/                /slides、/official 等文件與行政指令
   ├─ servers.example.json        伺服器清單範本（複製成 servers.json 填金鑰）
   └─ doc/使用教學.md             本文件
```

WSL 裡的檔案位置：`~/vllm-server/`（`.venv`、`vllm.env`、`run-vllm.sh`）、`~/.cache/huggingface/`（模型權重）、`~/bench-results/`（測試結果）。
安裝前的原本設定備份：`%LOCALAPPDATA%\vllm-opencode-backup\original-settings.json`（解除安裝時還原）。

## 13. 解除安裝

### 13.1 筆電（主機）

雙擊 **`server\wsl2\uninstall-host.cmd`**（會要求系統管理員權限），看過清單後輸入 `y`。

| 會移除 / 還原 | 說明 |
|------|------|
| Tailscale Funnel | 有開就關閉 |
| 排程 | `vLLM-WSL-KeepAlive`、Discord bot 的 `LocalLLM-DiscordBot`（並停止執行中的 bot） |
| WSL 裡的 vLLM | 服務 `vllm`、`~/vllm-server`（含金鑰）、`~/vllm-opencode-setup`、`~/bench-results`、本專案下載的模型；舊版的 llama-swap 也會一併移除 |
| 防火牆 | `vLLM-opencode-8000`（Windows + Hyper-V） |
| `.wslconfig` | 網路模式還原（回到安裝前的值；原本沒有就回 WSL 預設 NAT） |
| 電源 | 插電時睡眠、休眠、闔上螢幕還原成安裝前的值 |
| OpenSSH | 只有 `-EnableSsh` 開過時才還原 |
| 這台的 opencode | 程式與實驗室設定（同 13.2） |

**原本設定的備份**：`setup-host` 第一次安裝時，會把電源、`.wslconfig`、OpenSSH 的原本狀態記在
`%LOCALAPPDATA%\vllm-opencode-backup\`。解除安裝就是照這份還原。
如果是用**舊版 setup-host** 安裝的（當時還沒有備份），電源會改回 Windows 預設值（插電 30 分鐘睡眠、闔上螢幕 = 睡眠），
網路回到 NAT，OpenSSH 不動。結束時會列出這些項目，請自行確認。

| 參數 | 說明 |
|------|------|
| `-KeepModels` | 保留下載的模型（之後重裝不用再下載） |
| `-KeepOpencode` | 保留這台的 opencode |
| `-RemoveTailscale` | 連 Tailscale 一起解除安裝 |
| `-RemoveWsl` | **整個刪除 WSL Ubuntu**（裡面所有檔案都會消失，要再輸入發行版名稱確認） |

**不會動**：本 repo 的檔案（含 Discord bot 的 `.env`）、Scoop、Windows 端的 uv、WSL 裡的 apt 套件與 uv、你自己下載的其他模型。
最後會列出這些仍保留的東西和移除方式。

### 13.2 同學的電腦

- Windows：雙擊 **`opencode\client\uninstall-client.cmd`**。會移除設定裡的實驗室 provider、共用規則 `AGENTS.md`、文件工具 labdoc 與實驗室的 `/指令`，以及 opencode 程式（Scoop 或 npm 安裝的）。
  你自己加的其他 provider 和設定會保留；設定檔改動前會備份成 `opencode.json.uninstall-bak`。只想移除設定、保留程式：加 `-KeepProgram`。
- Ubuntu：`bash client/uninstall-client.sh`（可加 `--keep-program`）。
- 有裝桌面版的話，到「設定 → 應用程式」解除安裝。
